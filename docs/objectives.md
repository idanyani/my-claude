# Set objectives and priorities

Terms in *italics* are defined in [the index](README.md).

Work counts only when it serves a goal the developer holds. People push back on work that serves
nothing; agents do not, and *work outruns attention*. So the goals are written down where every
agent reads them, and the developer, not an agent, decides what work enters the backlog.

## In my-claude

- [purpose-review](../dot-claude/skills/purpose-review/SKILL.md) has the developer settle a repo's
  goals and non-goals in its README, and checks the repo against them;
  [project-review](../dot-claude/skills/project-review/SKILL.md) plans the large changes they call
  for.
- A review's findings become issues only when the developer picks them
  ([resolve-issue's workflow](../dot-claude/skills/resolve-issue/references/git-workflow.md)).

## Known gaps

- *Seen:* picking a proposed issue from a report is approval given under limited attention, not a
  priority the developer brought; their origin labels tell the two apart (see
  [measurement](measurement.md)), but nothing ranks them differently.
- *Seen:* a follow-up is not weighed against the goal it serves, so a chain of follow-ups can run
  while the goal does not advance.
